# CrewSense UI·신호 처리 통합 구현 계획

작성일: 2026-11-15 · 상태: 통합 구현 반영 · 현재 결과와 남은 범위는 [구현 상태](INTEGRATION_STATUS.md) 참조

## 1. 목표와 기준 코드

`nasa-space-app-2026`을 최종 앱 저장소로 사용한다. 기존 React 화면 구조와 디자인을 유지하고, PPG 처리와 혈압 추정 코어는 `../NASA`에서 가져온다. 사용자가 언급한 `nasa-space-2026`은 실제 폴더명 `nasa-space-app-2026`으로 해석한다.

| 역할 | 기준 코드 | 통합 방침 |
|---|---|---|
| 화면·디자인·라우팅 | `frontend/` | 대시보드, 일일 검사, 응급 화면, 카메라 UI와 디자인 토큰 유지 |
| 앱 서버·저장·기록 | `backend/app/` | FastAPI·SQLite·기록·메시지 기능 확장 |
| PPG 품질·필터·맥박수·PRV | `../NASA/sensing/` | 기존 계산과 테스트를 재사용하고 앱에 맞추기 위한 알고리즘 재작성은 피함 |
| 혈압 전처리·CPU 추론 | `../NASA/bp_experiment/preprocessing.py`, `cpu.py` | ECG+PPG 입력 계약과 동일 전처리 유지 |
| 혈압 학습·평가 | `../NASA/bp_experiment/` | 별도 연구 도구로 유지, 앱 시작 시 학습·다운로드하지 않음 |
| 시뮬레이션·응급 시나리오 | 앱의 persona·mock·protocol JSON | 명시적으로 선택한 데모 모드에서 유지 |

계획 작성 당시(2026-11-15) 확인 기준:

- 팀 앱은 백엔드 72개·프런트엔드 41개 테스트와 프로덕션 빌드를 통과했다.
- `backend/app/ppg/compute_vitals()`는 미구현이다.
- NASA PPG 코어는 8초 맥박수 window·60초 PRV window와 초기 안정화 구간을 사용한다. SpO₂·리듬 판정은 미구현이다.
- 혈압 실험은 동기화된 ECG+PPG 125Hz·각 1024점 입력을 요구한다. 현재 `output/bp_cpu/`와 `validation/bp_cpu_pilot.json`이 없어 학습된 모델과 최종 성능을 확인할 수 없다.
- 현재 앱의 혈압 화면은 커프 측정값 수동 입력이다.

이후 생성된 혈압 파일럿은 정확도 채택 기준을 통과하지 못했다. 통합 결과는 해당 모델을 비활성으로 유지한다.

## 2. 최종 구조와 소스 관리

```text
frontend/                       기존 팀 앱 화면
  src/state/SignalContext.tsx   세션별 공유 스트림 구독
  src/api/signals.ts            v2 API·WS 클라이언트
  src/lib/signalViewModel.ts    도메인 데이터 → 표시용 데이터
backend/app/
  signals/                     세션 관리·입력 어댑터·스트림 실행
  routers/signals.py           세션·수집·조회 API
  rules/                       출처·유효성에 따른 앱 판단
packages/crewsense-signals/
  src/crewsense_signals/
    ppg/                       NASA sensing의 계산·품질·스키마
packages/crewsense-bp/          선택 설치하는 NASA 혈압 전처리·CPU 추론 패키지
  tests/                       원본 회귀 테스트·통합 시나리오
research/bp/                   데이터 준비·학습·평가 CLI
docs/contracts-v2.md            통합 계약
```

- 통합 단계에서 NASA 코어를 위 독립 Python 패키지로 **한 번 이전**한다. 이후 앱의 계산 코어 수정은 이 패키지 한 곳에서 한다. `../NASA`는 이전 당시의 기준·검증 기록으로 남긴다.
- 원본 파일 해시·이전 내역·패키지 버전을 기록하고 원본 검증 결과와 비교한다. 두 폴더의 계산 코드를 번갈아 수정하는 구조를 만들지 않는다.
- 설치는 저장소 내부 패키지 의존성으로 고정한다. `sys.path` 조작이나 절대 경로 import를 사용하지 않는다.
- 하나의 FastAPI 앱에서 UI용 API와 신호 처리를 제공한다. `sensing.service`와 팀 서버를 같은 8000 포트에 따로 띄우지 않는다.
- PPG 코어의 핵심 런타임은 NumPy·SciPy·Pydantic이다. 혈압 추론도 NumPy·SciPy로 실행하고 PyTorch는 학습용 선택 의존성으로 분리한다.
- 대용량 파형·가중치·환자별 자료를 자동으로 Git에 포함하지 않는다. 로컬 artifact 경로와 해시를 설정으로 전달한다.

## 3. 공통 데이터 계약

### 3.1 모드와 출처

앱 동작 모드와 데이터 출처를 서로 다른 필드로 관리한다.

- 모드: `demo`, `measurement`, `research`.
- 출처: NASA의 `synthetic`, `public_replay`, `recorded_live`, `live`를 보존한다.
- 모든 세션에 `subject_id`, `session_id`, `device_id`를 연결한다. persona ID는 데모 전용이며 실측 대상자로 암묵 변환하지 않는다.
- 라이브 단절은 `stale` 또는 `disconnected`로 표시한다. 실측 도중 persona·mock으로 자동 대체하지 않는다.
- 데모의 리플레이·점프·배속은 유지한다. 모드를 변경하면 진행 중 검사와 누적 window를 종료하고 새 세션을 시작한다.

### 3.2 신호 출력

NASA `Snapshot`·`Metric`을 기준으로 v2 계약을 정의한다.

- 지표는 `value`, `unit`, `status`, `reason`, `method`, 측정 구간, 계산 시각, 유효기간을 가진다.
- `pulse_rate_bpm`, `ppg_rmssd_ms`, `spo2_pct` 명칭을 유지한다. `ppg_rmssd_ms`는 UI에서 PPG 기반 PRV로 표시하고 ECG-HRV와 합치지 않는다.
- 미지원 호흡수·리듬은 값이 없는 명시적 capability로 표현한다. `0`, `false`, 정상 범위 수치로 채우지 않는다.
- `quality`의 범주와 이유를 보존한다. 기존 `signal_quality: 0..1`로 임의 환산하지 않는다.
- 스트림 상태와 각 지표의 유효 상태를 구분한다. 연결이 살아 있어도 품질 불량·warming up이면 해당 숫자는 표시·판정하지 않는다.
- 임상 색상과 데이터 가용성을 분리한다. 데이터가 없으면 `assessment=not_assessed`, 색상·점수는 `null`로 하고 중립 스타일로 표시한다. 데이터 없음이 green/100점이 되지 않도록 한다.
- 기존 VitalsFrame은 데모 호환 입력으로 한정한다. 데모 변환 시 시뮬레이션 표시를 유지하고 실측 Snapshot을 강제로 필수 숫자 프레임으로 축소하지 않는다.

### 3.3 혈압 출력과 입력

- 커프 수동 입력과 모델 추정값을 별도 레코드로 저장한다. 공통 메타데이터는 출처·측정 구간·기록 시각·단위·대상자·세션이다.
- 커프 값은 `method=cuff_manual_entry`, 모델 값은 `method=ecg_ppg_model`, `model_version`, artifact 해시, `status=research_unvalidated`로 구분한다.
- 모델 결과는 `systolic_mmHg`, `diastolic_mmHg` 및 가용 상태를 가진다. 기존 `bp_sys/bp_dia`에는 커프 값을 유지하고 연구 추정값을 덮어쓰지 않는다.
- 현재 PPG `RawBatch`는 ECG 채널을 거부한다. 별도 `SynchronizedWaveformBatch`에 ECG·PPG를 명시하고, PPG 코어에는 PPG 채널만 투영해 전달한다.
- 혈압 입력은 공통 시계·동일 구간의 동기화된 두 채널을 요구한다. 모델 메타데이터의 125Hz·1024점 조건을 검증한다. 다른 입력률은 검증된 명시적 변환 어댑터만 허용한다.
- ECG가 없거나 시간 정렬·연속성·품질을 만족하지 못하면 혈압은 unavailable이다. PPG 단독으로 이 모델을 실행하지 않는다.

## 4. 구현 단계

### 단계 0 — 기준선과 계약 확정

작업:

- 기존 UI 주요 경로(`/`, `/check`, `/emergency`, `/reaction`, `/admin`)를 동일한 데모 조건으로 캡처한다.
- 두 프로젝트의 테스트와 기존 BIDMC 검증 결과를 기준선으로 보관한다.
- v2 계약, 모드 정책, source·subject·session 대응표를 `docs/contracts-v2.md`에 작성한다.
- 이후 변경은 전용 통합 브랜치에서 진행한다.

완료 기준: 어떤 화면을 유지하고 어떤 데이터 필드를 바꾸는지 추적 가능하며, 실측·데모·연구 데이터가 계약에서 구분된다.

### 단계 1 — NASA 코어 패키지 이전

작업:

- `sensing/schemas.py`, `quality.py`, `pipeline.py`, 입력 reader와 관련 테스트를 패키지로 이전한다.
- BP 전처리·CPU 추론은 별도 모듈로 이전하고, 학습·다운로드 코드는 연구 경로로 분리한다.
- 계산 방식·기본 window·필터·피크 검출 설정은 이전 과정에서 변경하지 않는다.
- 핵심 런타임과 연구 의존성을 분리해 설치·버전을 기록한다.

완료 기준: 동일한 BIDMC 입력에서 기존 맥박수·PRV·상태 전이가 재현된다. PyTorch 없이 앱과 BP CPU 추론 모듈을 import할 수 있다.

### 단계 2 — 세션별 신호 런타임

작업:

- 전역 `sensor.hub` 대신 대상자·세션·기기별 registry와 `Pipeline`을 만든다. 한 세션의 batch는 직렬 처리한다.
- 기존 10초 중첩 raw window 호출을 교체한다. 실제 batch를 한 번씩 처리해 causal filter와 60초 PRV 이력을 유지한다.
- 순번·시각·sample rate·채널 구성 검증과 gap 후 이력 초기화를 그대로 적용한다.
- 구독자가 늘어도 계산을 중복 실행하지 않는다. 구독 queue는 제한하고 느린 클라이언트에는 최신 상태를 우선한다.
- inactivity·EOF·에러·프로세스 종료·세션 전환의 상태를 전파한다. 서버와 브라우저 모두 유효기간 만료를 처리한다.
- 입력 크기와 처리 queue를 제한한다. 처리 중 batch가 누락되면 연속성이 끊겼음을 기록하고 window를 초기화한다.
- 센서가 없어도 BIDMC·합성·녹화 재생으로 이 경로를 실행할 수 있게 한다.

제안 API:

- `POST /api/v2/signal-sessions`: 대상자·입력·모드를 명시해 세션 시작.
- `WS /ws/v2/ingest?session_id=...`: 등록한 세션의 batch 수집. 대상자·기기 매핑을 서버에서 검증.
- `GET /api/v2/signal-sessions/{id}`: 상태·capability·최신 결과 조회.
- `WS /ws/v2/vitals?session_id=...`: Snapshot·stream status 구독.
- `POST /api/v2/signal-sessions/{id}/stop`: 입력과 구독 정리.

완료 기준: 두 대상자의 값이 섞이지 않으며, 새 구독자가 스트림을 재시작하지 않는다. 입력 단절 후 이전 숫자가 최신 수치로 남지 않는다.

### 단계 3 — 기존 UI에 새 데이터 연결

작업:

- `SignalContext`에서 세션별 WebSocket과 상태를 공유하고 `useVitals`, 카메라 pulse monitor, 응급 vitals가 같은 결과를 사용하게 한다.
- 표시 어댑터를 도입해 카드·차트의 기존 레이아웃을 유지한다. 숫자 외 warming up·no data·poor quality·stale 표시를 지원한다.
- `VitalsStrip`, `VitalCard`, `MetricsList`, `TrendChart`, `MeasureStep`, source 표시를 수정한다.
- PRV 표기와 단위를 수정한다. 미측정 SpO₂·호흡수·리듬은 미지원 상태로 표시한다.
- body map의 영역별 데이터 출처와 측정일을 추적한다. 실측 PPG가 없는 영역을 persona 기록으로 채우지 않는다. 수동 기록·설문·커프 값은 각각의 출처로 표시한다.
- REST 입력 오류·서버 오류·연결 실패를 분리한다. 실측 검사 저장 실패 시 예시 검사 결과를 성공 화면으로 보여주지 않는다.

완료 기준: 화면 배치와 이동 흐름은 기존 앱을 따르며, 누락·만료 데이터가 숫자·색상·추세로 정상 판정되지 않는다.

### 단계 4 — 일일 검사·기록 통합

작업:

- 검사 요청은 서버 세션과 앉기·서기 구간을 참조한다. 브라우저가 보낸 임의 프레임만으로 검사 결과를 확정하지 않는다.
- 구간별 유효 데이터·연속 길이·품질을 확인한다. 기준 미충족 시 재측정 또는 해당 항목 미측정으로 남긴다.
- `good or frames`를 제거한다. 과거 7일 값은 별도 이력으로 표시하고 오늘 측정값으로 승격하지 않는다.
- 앉기·서기 전환 시 이벤트를 기록하고 PRV 등 window가 두 자세를 가로지르는 경우 해당 구간 요약에서 제외한다. 기립 변화는 유효 구간이 있을 때만 계산한다.
- 일일 요약·커프 값·연구 혈압·세션 메타데이터를 분리 저장한다. 매초 파형 전체를 SQLite에 무제한 저장하지 않는다.
- schema migration은 기존 데모 기록을 보존한다. 반복 제출에는 검사 ID를 사용해 중복 기록·streak 증가를 방지한다.

완료 기준: 검사 결과에서 실제 사용한 구간·출처·지표 상태를 확인할 수 있고, 실측 이력이 없는 항목은 과거 persona 값으로 보충되지 않는다.

### 단계 5 — 경고·응급·예측 정책 정리

작업:

- 기존 흉통·무반응 프로토콜과 수동 응급 진입, 카메라 UI, 데모 경보 시나리오는 유지한다.
- 실측에서는 capability·신호 유효성·규칙 버전을 만족한 입력만 경고에 사용한다. 현재 NASA 코어의 실측 red flags 비활성 상태를 유지한다.
- 신호 불량·박동 검출 실패·stale·ECG 미지원 상태가 맥박 소실·부정맥 판정과 자동 CPR 진입으로 연결되지 않게 한다.
- 카메라 실측 탐지는 별도 튜닝 상태를 표시하고 기본 비활성으로 둔다. 데모의 자동 시나리오는 명시적으로 유지한다.
- 일별 실제 기록이 부족하면 time-to-act·이상 탐지를 unavailable로 둔다. placeholder 기준과 가상 30일 이력을 실측 예측에 사용하지 않는다.

완료 기준: 입력 실패로 자동 CPR이 실행되지 않는다. 기존 응급 데모는 명시적 데모 모드에서 동작하며 실측 화면과 데이터가 섞이지 않는다.

### 단계 6 — 혈압 연구 기능 연결

작업:

- 기존 커프 입력 화면을 유지하고 같은 검사 흐름 안에 별도 연구 추정 결과 영역을 추가한다.
- 가중치·메타데이터·최종 보고서·해시가 없으면 모델을 활성화하지 않는다. 파일럿 실행이 필요한 경우 기존 프로토콜을 그대로 사용한다.
- 완료된 과거 8.192초 ECG+PPG 구간에 기존 window-local 전처리와 NumPy CPUModel을 적용한다. PPG 맥박수용 필터 파형을 혈압 입력으로 재사용하지 않는다.
- 시간 단절·순서 오류·입력 채널 변경 시 BP window도 초기화한다. window 수집 시간과 계산 지연을 구분해서 표시한다.
- 결과는 연구용 추정으로 표시하고 커프 값과 별도로 기록·조회한다. 실측 경고·body map 건강 점수·응급 분기에는 자동 반영하지 않는다.
- 기존 채택 조건을 유지한다: SBP MAE ≤10mmHg, DBP MAE ≤7mmHg, window·환자별 평균 모두 baseline보다 10% 이상 개선, test ≥15명, 파라미터 ≤100만, artifact ≤4MiB, CPU p95 ≤1초 및 정상 혈압 순서. 실패·보고서 부재이면 통합 후보 활성화는 보류한다.
- 조건을 통과해도 연구 상태를 유지한다. 모델 추정값의 일반 측정값 승격이나 경고 사용은 이 계획의 범위에 포함하지 않는다.

완료 기준: ECG 없는 환경에서는 PPG는 계속 동작하고 연구 BP만 unavailable이다. 사용할 수 있는 모델이 있을 때 동일 입력의 CLI·API 결과가 일치한다.

### 단계 7 — 통합 검증과 실행 패키지

필수 시나리오:

1. 명시적 데모 모드: A/B/C·점프·응급·카메라 계산 회귀.
2. BIDMC 재생: 기존 평가 입력·설정으로 맥박수 기준선 비교.
3. startup/warmup: 맥박수와 PRV가 각 유효 window 이전에 나오지 않음.
4. dropout·noise·순서 오류·gap: 값 무효화와 이력 초기화.
5. 소스 중단·EOF·브라우저 단절: 만료 수치 제거, 자동 가상 수치 대체 없음.
6. 두 대상자·복수 구독: 세션 격리와 batch 단일 처리.
7. 일일 검사: 유효 데이터 없음·부분 측정·자세 전환·반복 제출·재시작 후 조회.
8. 혈압: ECG 없음·비동기 채널·결측·flatline·잘못된 모델·유효 artifact 입력.
9. 연구 혈압과 미지원 지표가 경고·CPR을 발생시키지 않음.
10. 인터넷 없이 설치 완료 환경에서 화면·모델 파일·재생 실행.

검증 수단은 기존 pytest·Vitest, 계약 테스트, 의미 있는 API·WebSocket 통합 테스트, 주요 사용자 흐름 브라우저 테스트다. UI는 기준 캡처와 비교하고 카메라·ESP32 하드웨어 검증 결과는 소프트웨어 테스트와 따로 기록한다.

완료 기준: 통합 테스트와 프런트엔드 빌드 통과, 데이터 출처·상태 표기 확인, 데모/실측/연구 시작 방법과 한계가 README에 정리됨.

## 5. 우선순위와 범위

| 우선순위 | 묶음 | 사용자에게 보이는 결과 |
|---|---|---|
| P0 | 단계 0–3 | 기존 UI에서 NASA PPG 맥박수·PRV와 품질·만료 상태 표시 |
| P1 | 단계 4–5 | 일일 검사·커프 기록·응급 데모가 출처를 보존하며 동작 |
| P2 | 단계 6 | 조건을 만족하는 모델·ECG+PPG가 있을 때 연구 혈압 표시 |
| 공통 | 단계 7을 각 단계에 적용 | 회귀·단절·격리·오프라인 동작 확인 |

PPG MVP는 P0+P1 완료로 정의한다. P2는 학습 결과와 ECG 입력 가용성에 의존하며 PPG MVP 완료를 막지 않는다. 새 센서 펌웨어, SpO₂ 보정, 리듬 알고리즘, 예측 모델 재학습, UI 전면 재설계는 별도 후속 작업이다.

첫 구현 단위는 **계약 v2 + 코어 패키지 이전 + BIDMC 한 세션을 기존 vitals 카드에 표시**하는 세로 단면으로 한다. 이후 세션 격리·일일 검사·경고 정책을 연결하고, 혈압 연구 기능을 추가한다.

후속 결정: 현재 혈압 모델은 기본 꺼짐인 선택 기능으로 분리했다. PPG 기본 패키지에 포함하지 않으며 서버 옵션과 연구 세션 옵션을 모두 선택해야 한다. 커프 입력은 기본 기능으로 유지한다. 자세한 동작은 INTEGRATION_STATUS.md와 contracts-v2.md를 따른다.
